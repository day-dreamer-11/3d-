## 摘要

本项目面向“工业数字工厂”教学、演示与方案验证场景，构建了一套从 **三维场景搭建** 到 **生产仿真、数据分析、边缘调度、优化归档** 的完整软件闭环。

平台以 Open Industry Project（OIP）作为三维场景编辑器，用户在浏览器中自由摆放输送机、检测装置、机器人、物料源与出口，保存后由桥接脚本把 OIP 工程转换为统一设备模型与显式物料连接表；随后由独立的 Python 离散事件引擎按固定步长、固定随机种子运行生产仿真，输出良品、产能、WIP、OEE、设备利用率、故障与能耗等指标。分析模块基于真实实验结果识别瓶颈并生成规则式优化建议；每个候选方案都必须真实重跑后才能进入对比，报告同时展示产能、周期与 OEE 的权衡，不隐藏不利结果。

工程侧完成了存储压缩、接口瘦身、缓存复用、实时实例清理、代码结构拆分与大工程自动保存等优化。演示数据存储从 173MB 降到 115MB，版本快照从约 19MB 降到 KB 级，场景列表读取从约 50ms 降到 1ms 以内；编辑器 20MB 工程的自动保存从“超出 localStorage 配额”变为可正常写入 IndexedDB；平台入口从 4427 行拆分为约 1930 行的五页应用与独立的旧页面模块。

交付侧提供 Windows 离线安装包 1.1.1（内置 Python 运行时、OIP 静态构建、演示数据），完成静默安装、启动、五页检查与卸载验证。全量自动化测试 79 项通过，浏览器端五页、OIP 编辑器、版本历史、演示重置等关键路径均实测无错误。

## 1. 项目背景与目标

### 1.1 背景

工业数字孪生与智能制造方案通常包含三维场景、产线仿真、数据分析、边缘计算与优化决策等多个环节，但实际演示中常见两类问题：

- 三维编辑器与生产仿真相互割裂，场景改动无法自动进入仿真；
- 演示数据与结果存在“写死”或只展示有利指标的情况，难以复现与追溯。

本项目把两者打通：OIP 负责“看见工厂”，Python 引擎负责“算出工厂”，所有 KPI 都来自本次场景的真实 tick 级仿真。

### 1.2 目标

1. 用户可以在浏览器中从空白地面搭建产线，无需安装 CAD 或桌面软件。
2. 场景保存后自动转换为统一设备模型和显式物料流，并能校验断流、环路、悬空设备。
3. 同一场景、同一随机种子、同一时长必须得到相同结果，支持离线复现。
4. 分析、优化、边缘调度与报告全部引用真实实验结果，不写死指标。
5. 提供可交付评委的 Windows 离线安装包，无需 Python、Node.js 或 Docker。

## 3. 核心功能

### 3.1 场景编辑器

- 新建/删除/切换场景，导入 OIP 工程 JSON；
- iframe 内嵌 OIP 编辑器，默认自动运行动画（仅视觉演示，不参与 KPI）；
- 保存后自动转换为统一设备模型，生成设备清单、显式连接和校验结果；
- 支持版本历史：版本列表、当前 vs 选中版本的设备增删/参数变化、一键恢复；
- 编辑器内支持“同步到 AIC”、实时仿真联动面板、故障/阻塞设备高亮。

### 3.2 建模分析工作台

单页串联五个阶段，并共享同一场景上下文：

1. **建模**：展示场景、设备、连接与校验；三维搭建跳转场景编辑器；
2. **采集数据**：离线确定性仿真或实时仿真；
3. **数据分析**：瓶颈、WIP、OEE 分解、设备利用率、三维状态快照；
4. **优化归档**：EdgeCoder、规则式建议、What-if、优化应用、实验对比；
5. **报告**：生成 JSON / Markdown / HTML 报告。

顶部进度条按实际数据点亮：建模 → 采集 → 分析 → 优化 → 报告。

### 3.3 仿真引擎

- 每个设备单服务台 + 有限队列；
- 输送机节拍 = 长度 / 速度；检测/机器人按参数节拍；
- 下游容量满时进入 blocked，只重试传递，不重复加工或重复判定；
- 故障按指数间隔发生、按 MTTR 维修，维修期间停机；
- 所有指标来自 tick 级统计：良品、不良、WIP、吞吐、OEE、平均周期、能耗、故障、利用率；
- 相同场景 + 相同 seed + 相同时长 ⇒ 相同结果（离线实验）。

### 3.4 边缘计算与优化

- 从本次场景事件生成计算任务：视觉检测、质量判定、故障预警、设备监测、生产调度；
- 固定本地、固定云端、动态调度三种策略共享同一任务集，输出满足率、平均/P95 时延、超时、拒绝、成本；
- 瓶颈分析基于真实设备利用率与队列；
- 优化建议为规则式候选，但每个候选必须真实重跑后才参与评分；
- 应用优化会生成新的场景版本和新实验，历史版本与历史实验均保留。

### 3.5 实验历史与项目文件

- 实验记录保存场景快照、场景版本、seed、时长、KPI、事件与设备状态；
- 历史实验不受后续场景修改影响；
- 支持同场景基线与候选实验对比；
- 整包导出为单文件 `.aicproj`（ZIP）：项目、场景、OIP 工程、版本、实验、报告；
- 导入始终创建新项目，保留场景/实验 ID，校验路径穿越与解压体积。

### 3.6 演示与重置

- 侧栏「一键演示」：自动选择有设备的演示场景 → 运行离线仿真 → 跳转分析结果；
- 系统设置「重置演示项目」：从 `demo_seed` 恢复演示数据，同名旧项目先归档；
- 工作台进度条与场景版本历史便于评委快速理解完整链路。

## 4. 关键技术

### 4.1 统一场景模型

`SceneDocument` 包含设备、显式连接、几何候选、校验结果、仿真设置与 OIP 原始工程。设备 ID 直接使用 OIP `part.id`，跨导入稳定；空间关系与业务关系分离：

- `geometry_candidates` 只是几何建议，不参与仿真；
- `connections` 是仿真唯一使用的显式物料流；
- 设备移动不会自动改写业务连接，只产生几何错位 warning。

### 4.2 确定性离散事件引擎

引擎使用固定 `tick_sec`、单一 `random.Random(seed)`，不依赖 wall-clock。离线实验是确定性权威；实时实验由线程按 wall-clock 推进，只用于演示，不承诺逐位复现。

金标回归（固定场景、seed=11、600s）：

| 指标 | 值 |
|---|---|
| 良品 | 66 |
| 不良 | 7 |
| 吞吐 | 396 件/小时 |
| WIP | 9 |
| OEE | 0.7956 |

### 4.3 显式连接与校验

校验覆盖：设备/端口不存在、自连接、端口方向或物料类型不匹配、重复连接、仅展示设备混入物料流、物料流环路、缺少 Spawner/Despawner、从源不可达出口、非法位置/参数等。错误会阻止仿真并返回明确原因。

### 4.4 内容寻址存储与轻量版本

- OIP 工程按内容哈希存 `scenes/<sid>/oip/<hash>.json`，相同工程只存一份；
- `scene.json` 与版本快照只存 OIP 哈希引用；
- 列表页读取 `summary.json`，不再解析约 20MB 的工程；
- 旧格式数据保持可读，并提供 `tools/compact_scene_storage.py` 幂等迁移。

实测：两个演示项目与 `demo_seed` 合计从 173MB 降到 115MB；版本文件从约 19MB 降到 KB 级；`list_scenes` 从约 50ms 降到 1ms 以内。

### 4.5 大工程自动保存与旧缓存自愈

OIP 自带自动保存使用 localStorage，配额通常只有 5–10MB，而演示工程约 20MB，会触发 “Not saving”。平台在桥接层增加 IndexedDB 溢出层：

- 小键值仍走 localStorage；
- OIP 工程键与超大值写入 IndexedDB，并按项目 + 场景隔离；
- 刷新后若存在未同步编辑，自动恢复并提示同步；
- 进入编辑器前经过同源 `reset.html`，注销 OIP 旧 Service Worker 并清理缓存；
- 内嵌模式禁用 SW 注册，避免继续加载旧版桥接脚本。

实测：20MB 工程 `persistProject()` 返回 ok，IndexedDB 记录 19.9MB；重载后提示“已恢复本地未同步编辑”；预置旧 SW（1 个 registration + 1 个 cache）后进入编辑器，两者均清零，0 告警。

### 4.6 缓存、接口瘦身与结构拆分

- Streamlit 项目/实验摘要按目录指纹缓存，写操作后自动失效；
- `SceneClient` 复用连接，避免每次重跑新建 HTTP 客户端；
- `GET /scenes/{sid}` 默认不返回约 20MB 的 OIP 工程；`load_scene(include_oip=False)` 让仿真/校验按需加载；
- 实时仿真管理器只保留最近 20 个已结束实例，实例 ID 全局唯一，避免内存持续增长；
- `factory_app.py` 从 4427 行拆分为约 1930 行主入口 + `legacy_pages.py` / `ui_shared.py` / `ui_cache.py`。

## 8. 已知限制与边界

1. OIP 仍为 pre-1.0，已固定提交；升级需重新验证桥接、映射与构建。
2. 连接推导是几何启发式；track/mount/edge/chain 等吸附关系未完整复刻。
3. 引擎为单服务台简化模型，不支持复杂合流/分流优先级与累积输送物理。
4. OEE 为线级简化公式；提速后 OEE 可能下降，报告如实展示权衡。
5. 实时实验由 wall-clock 推进，非逐位复现；离线实验才是确定性权威。
6. 当前仅监听 127.0.0.1，无鉴权与多用户；远程部署需反向代理与认证。
7. 优化器为规则式有限候选，不做网格/贝叶斯搜索。
8. 所有 KPI、OEE、能耗、边缘时延均为软件仿真，不是真实工厂或 6G 实测。
